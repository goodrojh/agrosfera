# АгроСфера — сводка предложений предприятий и сделки с экспортёрами

АгроСфера работает как брокер. Предприятия-партнёры (проверенные заранее) каждый день в 8:00 по местному времени получают сообщение от бота в Telegram / MAX и отвечают одной строкой: цена, объём, влажность, сорная примесь, масличность (или протеин). Сайт в реальном времени публикует сводку предложений без названий предприятий и график цен по регионам. Экспортёры оставляют заявку на предложение или общий запрос — заявки приходят менеджеру в панель и в Telegram.

## Структура

| Путь | Что это |
|---|---|
| `app/`, `components/site/` | Сайт (Next.js, статический экспорт для GitHub Pages): главная со сводкой, «Экспортёрам», «Предприятиям» (анкета партнёра), «О нас», «FAQ» |
| `components/market/` | Сводка: график, таблица предложений, форма заявки, симулятор бота, источник данных (демо или сервер) |
| `lib/market/` | Общая логика сайта и бота: культуры и показатели качества, регионы и часовые пояса, разбор ответа, защита от ошибок, расчёт индекса |
| `server/` | Бот Telegram + MAX, база SQLite, API для сайта, панель управления `/admin` |

## Ответ предприятия и защита от ошибок

- Формат — одна строка: `ЦЕНА ОБЪЁМ ВЛАЖНОСТЬ СОРНАЯ_ПРИМЕСЬ МАСЛИЧНОСТЬ`, например `31500 200 8 1.5 46`. У пшеницы, ячменя и сои последнее число — протеин, у нута его нет (4 числа). Понимает «31 500», «1,5», «31,5 тыс».
- Бот повторяет, что понял. `30 …` → «Похоже, цена в тысячах: 30 → 30 000 ₽/т?» с кнопкой; лишний ноль ловится так же.
- Показатели вне диапазона (влажность 1–25%, сорная примесь 0–20%, масличность/протеин — по культуре) не принимаются: бот подсказывает порядок чисел.
- Отклонение цены от медианы больше 15% — переспрашиваем, больше 35% — цена уходит на проверку менеджеру и до решения не публикуется.
- «Сегодня нет в продаже» снимает предложение со сводки. Без ответа предложение живёт 3 дня.

Пороги — `lib/market/validate.ts` (`LIMITS`), диапазоны показателей — `lib/market/crops.ts`.

## Сайт локально

```bash
npm install
npm run dev
```

Без `NEXT_PUBLIC_API_URL` сайт работает на **демо-данных** (плашка «демо-данные» в терминале): история за 90 дней и поток подач генерируются в браузере.

Деплой на GitHub Pages: `bash scripts/deploy-pages.sh` (собирает сайт и публикует в ветку `gh-pages`).

Автодеплой при каждом пуше: выполнить `gh auth refresh -s workflow`, затем переложить `deploy/github-actions-deploy.yml` в `.github/workflows/deploy.yml` и в настройках Pages выбрать источник «GitHub Actions».

## Запуск бота и API (сервер)

Нужен Node.js 22.13+ и сервер с HTTPS (сайт на https, поэтому API тоже должен быть https).

1. Создать бота в Telegram через [@BotFather](https://t.me/BotFather), получить токен.
2. (Опционально) Создать бота в MAX на [платформе для партнёров](https://dev.max.ru), получить токен.
3. Создать чат для менеджеров, добавить туда бота, узнать id чата — туда будут приходить заявки с сайта и цены на модерацию.
4. На сервере:
   ```bash
   cd server
   cp .env.example .env   # заполнить токены, ADMIN_CHAT_ID, CORS_ORIGIN
   npm install
   npm run selftest       # проверка диалога бота без мессенджеров
   npm start
   ```
5. Завести предприятия и отправить им ссылки-приглашения:
   ```bash
   npm run admin -- regions
   npm run admin -- add "ООО Лён Сибири" altai 2200000000
   ```
6. В репозитории: **Settings → Secrets and variables → Actions → Variables** добавить
   `API_URL` (например `https://api.example.ru`), `TELEGRAM_BOT_URL`, `MAX_BOT_URL`, `CONTACT_EMAIL` и перезапустить workflow — сайт переключится с демо на живые данные. Без Actions — те же значения передать при ручном деплое: `NEXT_PUBLIC_API_URL=https://api.example.ru bash scripts/deploy-pages.sh`.

### Партнёры: анкета и проверка

1. Предприятие заполняет анкету «Стать партнёром» на странице «Предприятиям» (название, ИНН — необязательно, регион склада, культуры, контакт, телефон).
2. Анкета появляется в панели во вкладке **«Анкеты»**. Менеджер звонит, проверяет документы, отмечает культуры и ставит галочку **«Доступ открыт»**.
3. Предприятие открывает бота и нажимает **«Отправить номер»** (номер должен совпасть с анкетой) или переходит по личной ссылке из карточки.
4. Каждый день в 8:00 по часовому поясу региона бот просит предложение по каждой культуре; в 11:00 напоминает тем, кто не ответил. Сообщение уходит один раз в день, даже если сервер перезапускался.

### Панель управления

`http://<сервер>:8080/admin`, пароль — `ADMIN_PASSWORD` в `server/.env`. Вкладки:

- **Заявки** — от экспортёров: на конкретное предложение (видно, чьё оно — предприятие и контакт) или общий запрос. Статус «Новая / В работе / Сделка / Отказ».
- **Партнёры** — карточка предприятия (доступ, культуры, контакты, заметки, приглашение в бот, «Запросить предложение сейчас») и отметка, ответил ли партнёр сегодня.
- **Анкеты** — новые предприятия с сайта. **Цены на проверке** — сильно отличающиеся от рынка.

Уведомления о заявках и анкетах в Telegram: напишите боту `/id` и укажите ID в `ADMIN_CHAT_ID`.

### Бот для предприятий

- Работает только с участниками, у которых в панели открыт доступ; незнакомым предлагает заполнить анкету партнёра на сайте.
- Ответ — одна строка `ЦЕНА ОБЪЁМ ВЛАЖНОСТЬ СОРНАЯ_ПРИМЕСЬ МАСЛИЧНОСТЬ`, например `31500 200 8 1.5 46`. По названию культуры: «подсолнечник 38500 300 7 2 49».
- `/price` — прислать предложение сейчас, `/status` — мои предложения в сводке, `/help` — подсказка.

### API

- `GET /api/snapshot?crop=flax` — предприятия с открытым доступом (анонимно: код и регион), ответы за последние 4 дня (из них сводка и график за день), дневные закрытия за 90 дней.
- `GET /api/stream` — SSE: события `quote` (новый ответ предприятия), `company`.
- `GET /api/summary` — свободный объём по России на сегодня по каждой культуре (первый экран).
- `POST /api/leads` — заявка экспортёра: `{ offerId?, crop, regions?, volume?, price?, name, company, phone, comment }`.
- `POST /api/apply` — анкета предприятия «Стать партнёром».

Проверить бота без Telegram: `npm run selftest` (в `server/`). Наполнить тестовую базу для проверки сайта: `DB_PATH=./data/test.db npx tsx src/seed-demo.ts`.
