# АгроСфера — котировки масличного льна

Инструмент прозрачности рынка: производители каждое утро присылают в бот (Telegram / MAX) цену за тонну и свободный объём, сайт в реальном времени показывает индекс, диапазон цен, объёмы и разбивку по регионам и направлениям экспорта (Китай, Казахстан и Ср. Азия, Каспий, Чёрное море).

## Структура

| Путь | Что это |
|---|---|
| `app/`, `components/site/` | Сайт (Next.js, статический экспорт для GitHub Pages): главная с котировками и страница `/sotrudnichestvo` для партнёров |
| `components/market/` | Терминал: график, симулятор бота, источник данных (демо или сервер) |
| `lib/market/` | Общая логика сайта и бота: регионы, разбор сообщений, защита от ошибок, расчёт индекса |
| `server/` | Бот Telegram + MAX, база SQLite, API для сайта (снимок + поток SSE + заявки) |

## Защита от ошибочных цен

- Бот повторяет, что понял. `30 150` → «Похоже, цена в тысячах: 30 → 30 000 ₽/т?» с кнопкой подтверждения; лишний ноль ловится так же.
- Цена вне 10 000–100 000 ₽/т не принимается.
- Отклонение от медианы региона больше 15% — переспрашиваем, больше 35% — цена уходит модератору (кнопки в админ-чате Telegram) и до проверки не участвует в индексе.
- Индекс — медиана с отсечением выбросов (MAD), поэтому одиночная ошибка его не сдвигает.
- Повторная отправка за день заменяет прежнюю цену предприятия, история сохраняется.

Пороги — в `lib/market/validate.ts` (`LIMITS`).

## Сайт локально

```bash
npm install
npm run dev
```

Без `NEXT_PUBLIC_API_URL` сайт работает на **демо-данных** (плашка «демо-данные» в терминале): история за 90 дней и поток подач генерируются в браузере.

Деплой на GitHub Pages: `bash scripts/deploy-pages.sh` (собирает сайт и публикует в ветку `gh-pages`).

Автодеплой при каждом пуше: выполнить `gh auth refresh -s workflow`, затем переложить `deploy/github-actions-deploy.yml` в `.github/workflows/deploy.yml` и в настройках Pages выбрать источник «GitHub Actions».

## Запуск бота и API (сервер)

Нужен Node.js 22.13+ и сервер с HTTPS (сайт на https, поэтому API тоже должен быть https).

1. Создать бота в Telegram через [@BotFather](https://t.me/BotFather), получить токен.
2. (Опционально) Создать бота в MAX на [платформе для партнёров](https://dev.max.ru), получить токен.
3. Создать чат для менеджеров, добавить туда бота, узнать id чата — туда будут приходить заявки с сайта и цены на модерацию.
4. На сервере:
   ```bash
   cd server
   cp .env.example .env   # заполнить токены, ADMIN_CHAT_ID, CORS_ORIGIN
   npm install
   npm run selftest       # проверка диалога бота без мессенджеров
   npm start
   ```
5. Завести предприятия и отправить им ссылки-приглашения:
   ```bash
   npm run admin -- regions
   npm run admin -- add "ООО Лён Сибири" altai 2200000000
   ```
6. В репозитории: **Settings → Secrets and variables → Actions → Variables** добавить
   `API_URL` (например `https://api.example.ru`), `TELEGRAM_BOT_URL`, `MAX_BOT_URL`, `CONTACT_EMAIL` и перезапустить workflow — сайт переключится с демо на живые данные. Без Actions — те же значения передать при ручном деплое: `NEXT_PUBLIC_API_URL=https://api.example.ru bash scripts/deploy-pages.sh`.

### Личный кабинет и проверка участников

Публичный сайт показывает график и стакан без действий. Работать с инструментом можно только из личного кабинета (`/kabinet/`, вход по email и паролю).

1. Предприятие, экспортёр или агент регистрируется в кабинете: роль, компания, ИНН (необязательно), регион, контакт, телефон, email/пароль; предприятие отмечает культуры.
2. Регистрация появляется в панели во вкладке **«Анкеты»**. Менеджер звонит, пишет заметки, у предприятия закрепляет культуры и ставит галочку **«Доступ открыт»**.
3. После этого в кабинете: предприятие подаёт цены по своим культурам (и может подключить бота), экспортёр/агент ставит заявки на покупку; в терминале открываются кнопки «купить/продать по цене из стакана».
4. Бот: предприятие нажимает «Подключить бота» в кабинете (личная ссылка) или «Отправить номер» в боте. Каждое утро (пн–сб, в `REMINDER_HOUR` по Москве) бот спрашивает цену и объём по каждой закреплённой культуре.

### Панель управления

`http://<сервер>:8080/admin`, пароль — `ADMIN_PASSWORD` в `server/.env`. Вкладки:

- **Совпадения** — заявка покупателя не ниже цены предприятия (проверяется при каждой новой цене и при одобрении заявки). Видно обе стороны с контактами; статус «Новое / В работе / Сделка / Отказ». Кнопка **«Сообщить сторонам»** — предприятию приходит сообщение в бот, обеим сторонам совпадение показывается в кабинете. До этого стороны о совпадении не знают. Менеджеру уведомление приходит сразу (в Telegram при `ADMIN_CHAT_ID`).
- **Участники** — карточка: роль, доступ, культуры, контакты, заметки, **«Сбросить пароль»** (выдаёт временный), приглашение в бот.
- **Заявки покупателей** — в стакан попадают после «В стакан»; **Цены на проверке** — сильно отличающиеся от рынка; **Запросы на сделку** — нажатия «купить/продать» в терминале.

Уведомления в Telegram: напишите боту `/id` и укажите ID в `ADMIN_CHAT_ID`.

### Бот для предприятий

- Работает только с участниками, у которых в панели открыт доступ; незнакомым предлагает зарегистрироваться в личном кабинете.
- Ответ — `ЦЕНА ОБЪЁМ`, например `31500 200`. Понимает и «32 500 руб 150 т», «цена 31 тыс, объём 300». По названию культуры: «подсолнечник 38500 300».
- `/price` — прислать цены сейчас, `/status` — мои цены сегодня, `/help` — подсказка.

### API

- `GET /api/snapshot?crop=flax` — участники с открытым доступом по культуре (анонимно: код и регион), подачи за сегодня, дневные закрытия за 90 дней, заявки покупателей.
- `GET /api/stream` — SSE: события `quote`, `company`, `reset` (смена дня).
- `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/logout` — кабинет (токен в `Authorization: Bearer`).
- `GET /api/me` — профиль, цены за сегодня, заявки, совпадения (после уведомления менеджером).
- `POST /api/cabinet/quote` — цена предприятия; `POST /api/cabinet/bids`, `POST /api/cabinet/bids/:id/cancel` — заявки покупателя; `POST /api/cabinet/deal` — запрос на сделку; `POST /api/cabinet/password`. Действия — только при открытом доступе.

В `GET /api/snapshot` есть поле `bids` (активные заявки покупателей за 14 дней), в потоке `/api/stream` — событие `bid`.
